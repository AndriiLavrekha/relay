# Agent Task Bridge v0.3.0

Agent Task Bridge v0.3.0 makes ChatGPT results integrate cleanly. The release adds three things:

- worker-side tooling, so ChatGPT never hand-writes hashes;
- checks and a three-way merge before anything is staged;
- local validation that runs on real projects.

Protocol `1.0` and schema `1.1` are unchanged. Capsules and results from v0.2.x remain readable. Reported `bridge_version` and `exporter_version` are `0.3.0`.

## Worker side

- Every Task Capsule carries an **Integration Contract**:
  - plan first;
  - match the embedded conventions;
  - add no dependencies;
  - keep `contract` signatures;
  - return complete files with no placeholders;
  - add tests per acceptance criterion;
  - report only commands actually run.
- **Option A, `pack_result.py`.** The capsule embeds a stdlib-only Python script with the task ID, base commit, and baseline hashes filled in. On ChatGPT Plus, ChatGPT runs it and returns a Result Capsule ZIP.
- **Option B, text reply.** Without code execution (for example ChatGPT Go), ChatGPT replies in `<<<ATB_RESULT:...>>>` framing. Save the reply as a `.md` file; `import` builds the ZIP and computes hashes locally.

## Import

- `import` accepts a ZIP or a saved text reply.
- Returned files take the baseline's line endings.
- Abbreviated files are withheld as `SUSPECT_ELISION`. That covers placeholder comments such as `// ... existing code` and a large unexplained shrink. After review, `--allow-elision` stages them.
- Files you changed locally while ChatGPT worked are merged three-way against the stored baseline. A clean merge stages as `MERGED_CLEAN`. Overlapping edits keep a conflict-marker candidate.
- `import --brief` and `review --brief` print decisions, drift, withheld files, and failing output tails only.
- Result manifests can no longer name a stored task outside the task directory (`UNSAFE_TASK_ID`).

## Validation

- Git-ignored `node_modules`, `vendor`, `.venv`, and `venv` directories are linked into staging for the run. Staged validation previously failed on any project with installed dependencies.
- Staging cleanup detaches those links first. `git worktree remove --force` follows Windows junctions.
- Toolchain caches stay reachable: Cargo, rustup, NuGet, Go, `DOTNET_ROOT`, and `JAVA_HOME`.
- Discovery adds `cargo test`, `go test ./...`, `dotnet test`, CMake + CTest, pytest, and Composer/PHPUnit, each only when the tool is installed.
- `.agent-task-bridge/config.json` gains two keys:
  - `validationCommands` replaces discovery;
  - `validationTimeoutMs` sets the per-command timeout.

## Follow-up and integrate

- `follow-up` re-exports from the current checkout. It embeds integrated work and withheld files instead of the original baseline.
- `integrate --mode branch` runs Git in the repository rather than the process directory. It commits the staged files on the new branch and removes its temporary worktree. On commit failure, it keeps the worktree and reports `commitError`.

## Behavior changes

- Branch-mode `integrate` now creates a commit on the new branch.
- The capsule's fixed overhead grows by about 1–2k estimated tokens for the packer script and contract. Re-check `maxTokens` budgets that sit near their limit.
- In pnpm/yarn workspaces and with Python editable installs, linked dependencies still point at the active repository. Use `validationCommands` for per-package checks.

## Verification

```text
npm test
npm run smoke
npm run bundle:plugins
npm pack --dry-run
```

The Windows host for this release ran 171 tests: 164 passed and 7 Windows symlink and reparse-point tests were skipped. A real xUnit solution passed `dotnet test` in staging. C++, Rust, Go, and PHP validation were not run against real toolchains.

## Install

The repository is private. Installation uses your Git credentials.

- Claude Code: `/plugin marketplace add AndriiLavrekha/relay@v0.3.0`, then `/plugin install task-bridge@awesome-task-bridge`.
- Codex: `codex plugin marketplace add AndriiLavrekha/relay --ref v0.3.0`, then `codex plugin add task-bridge@awesome-task-bridge`.
