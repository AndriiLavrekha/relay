# Agent Task Bridge v0.2.0

Agent Task Bridge v0.2 strengthens the manual Task Capsule / Result Capsule workflow while preserving protocol `1.0` compatibility.

## Included

- schema `1.1` metadata for Task and Result Capsules;
- complete-capsule privacy scanning with block, confirmation, allow, and metadata-only redact policies;
- SHA-256 and raw-byte-length verification for every returned file;
- returned-file and `REPORT.md` scanning before staging;
- transactional imports with recoverable failed/interrupted records;
- external isolated staging, selective working-tree reconstruction, same-volume fallback, and symlink/junction protections;
- scrubbed validation environments, safe/prompt/skip policies, bounded output, timeouts, and process-tree termination;
- acceptance-criteria evidence separated into worker claims and local evidence;
- generated kickoff/upload/contract/summary handoff bundles;
- lifecycle records, immutable receipts, persisted review reports, follow-up capsules, and confirmation-gated integration;
- integration is a separate `integrate <import-id> --confirm` action after review;
- context byte/token estimates with safety margin, per-file breakdown, and `--max-tokens`.

## Compatibility

`atb_protocol` remains `1.0`. Legacy Task Capsules and Result Capsules without `schema_version` remain readable. Legacy Result Capsules receive a `legacy_integrity` warning and do not receive an unqualified complete-result interpretation.

## Workflow additions

```text
node bin/agent-task-bridge.mjs task show <task-id> --repo .
node bin/agent-task-bridge.mjs review <import-id> --repo .
node bin/agent-task-bridge.mjs follow-up <import-id> --repo .
node bin/agent-task-bridge.mjs integrate <import-id> --repo . --mode branch --branch bridge/<name> --confirm
```

The normal transport remains manual file upload/download. Automatic API or browser transport is deferred. OS-level sandboxing for validation is also deferred; v0.2 provides environment scrubbing, network-policy hooks, resource bounds, and explicit validation policy controls within the Node process model.

On Windows, external staging has a same-volume fallback and validation timeout handling uses the platform process-tree termination path available to the runtime. Junction/reparse-point coverage that requires a Windows CI host remains a release follow-up.

## Verification handoff

The intended release tag is `v0.2.0`. Before publication, run:

```text
npm test
npm run smoke
npm run bundle:plugins
npm pack --dry-run
```

Provider marketplace references and plugin manifests are expected to use `0.2.0`. Publication, tagging, and marketplace deployment are separate user-authorized actions.

## Deferred backlog

Automatic transport, encrypted local storage, enterprise policy packs, provider-specific token pricing, binary context support, and broader Node/platform CI remain outside this release.
