# Agent Task Bridge v0.2 Import Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move executable staging outside the repository and make import drift, operation semantics, cleanup, reparse-point handling, and active-tree invariance deterministic.

**Architecture:** Keep `src/importer.mjs` as the orchestration boundary, but move staging-location, working-tree reconstruction, cleanup, and active-tree fingerprinting into focused functions in `src/staging.mjs`. Extend `src/drift.mjs` with explicit operation preconditions. The importer stages only clean, in-scope files and persists recoverable failure records without modifying the active worktree.

**Tech Stack:** Node.js 22+ native ESM, `node:fs/promises`, `node:os`, `node:path`, Git worktrees, Node built-in `node:test`.

## Global Constraints

- Keep `atb_protocol: "1.0"`; do not change the v0.1 capsule transport in this plan.
- Staging must be outside the active repository and must never be silently relocated inside it.
- The active worktree remains read-only during export and import.
- Do not copy unrelated untracked or ignored files into staging.
- Reject or quarantine symlinks, junctions, and other reparse-point paths.
- Preserve zero third-party runtime dependencies, native ESM, and Windows/macOS/Linux support.
- Run `npm test` after each task group and retain staging/report artifacts needed for review.

## File and interface map

- Modify `src/staging.mjs`: staging-root resolution, volume checks, selective reconstruction, reparse checks, cleanup, and active-tree fingerprints.
- Modify `src/importer.mjs`: transaction lifecycle, strict staging decisions, failure persistence, and before/after assertions.
- Modify `src/drift.mjs`: operation preconditions and explicit classification for invalid operations.
- Modify `src/storage.mjs`: safe failure-record paths without copying sensitive result payloads.
- Modify `src/errors.mjs`: staging and lifecycle error codes.
- Create `test/staging.test.mjs`: staging-location, reconstruction, cleanup, and fingerprint tests.
- Modify `test/drift.test.mjs`: strict create/modify/delete precondition tests.
- Modify `test/importer.test.mjs` and `test/security.test.mjs`: transactional import and reparse-point coverage.

- [ ] **Step 3: Implement operation-aware classification**

Check scope first, then apply these rules:

```js
if (operation === 'create') {
  return baseline.has(path) || current.exists ? 'INVALID_OPERATION_PRECONDITION' : 'NEW_EXPECTED';
}
if (operation === 'modify' || operation === 'delete') {
  if (!baseline.has(path) || !current.exists) return 'INVALID_OPERATION_PRECONDITION';
  return current.sha256 === baseline.get(path).sha256 ? 'CLEAN_UNCHANGED' : 'LOCAL_CHANGED';
}
return 'INVALID_OPERATION_PRECONDITION';
```

Keep `OUT_OF_SCOPE` higher priority than operation checks. Make `result-capsule.mjs` reject invalid operation values before import and preserve the importer classification for valid values with invalid repository preconditions.
