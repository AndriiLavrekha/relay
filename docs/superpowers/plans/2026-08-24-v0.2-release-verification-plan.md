# Agent Task Bridge v0.2 Release Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the canonical runtime, Claude Code bundle, Codex bundle, protocol documentation, README workflow, and release artifacts synchronized after the v0.2 pillars are implemented.

**Architecture:** Continue treating `src/` and `bin/` as canonical. `scripts/bundle-plugins.mjs` regenerates provider runtimes, `test/plugin-adapters.test.mjs` proves byte synchronization, and the final verification sequence exercises unit tests, cross-provider smoke flows, package contents, and documentation claims. CI and platform-matrix expansion remain outside this release plan.

**Tech Stack:** Node.js 22+ native ESM, existing bundle script, Node built-in `node:test`, npm package tooling, Claude/Codex plugin manifests.

## Global Constraints

- The project requires Node.js 22 or newer.
- Runtime dependencies remain zero third-party packages.
- Generated provider runtimes must match `src/` and `bin/` exactly.
- Preserve Claude Code and Codex marketplace metadata and installation instructions.
- Do not add CI or automated transport in this plan.
- Release verification must run sequentially because `prepack` regenerates provider bundles.

## File and interface map

- Modify: `scripts/bundle-plugins.mjs` only when new canonical files require inclusion.
- Modify: `plugins/claude-code/runtime/` and `plugins/codex/runtime/` only through the bundle script.
- Modify: `plugins/claude-code/skills/` and `plugins/codex/skills/` when workflow text changes.
- Modify: `protocol/TASK-CAPSULE-v1.md`, `protocol/RESULT-CAPSULE-v1.md`, `docs/architecture.md`, and `README.md` to match shipped behavior.
- Modify: `package.json` and plugin manifests for the v0.2 version only after implementation gates pass.
- Modify/create: `docs/releases/v0.2.0.md` for release notes and known limitations.
- Modify: `test/plugin-adapters.test.mjs`, `test/e2e.test.mjs`, and documentation/package assertions.
