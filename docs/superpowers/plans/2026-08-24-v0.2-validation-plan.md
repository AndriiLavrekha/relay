# Agent Task Bridge v0.2 Validation Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run trusted validation commands with a scrubbed environment, recursive configuration checks, bounded output/time, and platform-correct process-tree termination.

**Architecture:** Keep command discovery and validation policy in `src/validation.mjs`, while `src/process.mjs` owns bounded child-process execution and platform-specific termination. Import captures the trusted snapshot before applying returned files and refuses to execute when the snapshot is invalidated. Validation claims are persisted as local evidence for the reporting and receipt plans.

**Tech Stack:** Node.js 22+ native ESM, `node:child_process`, `node:fs/promises`, `node:os`, Windows `taskkill.exe`, POSIX process groups, Node built-in `node:test`.

## Global Constraints

- Validation commands come from the trusted pre-import snapshot, never from returned Result Capsule instructions.
- Default policy is `safe`; `prompt` requires explicit confirmation; `skip` executes nothing.
- Scrub credentials and agent variables from child environments.
- Apply per-command timeout, total timeout, and output limits.
- Terminate the full process tree on timeout/interruption.
- On Windows use `taskkill.exe /PID <pid> /T /F`; on POSIX use a detached process group and negative-PID signals.
- Keep zero third-party runtime dependencies, native ESM, Node.js 22+, and provider runtime synchronization.

## File and interface map

- Modify `src/process.mjs`: bounded spawn, sanitized environment, output limits, timeout, and tree termination.
- Modify `src/validation.mjs`: recursive configuration snapshot, validation modes, provenance, and command execution options.
- Modify `src/importer.mjs`: capture trusted snapshot, enforce drift/config policy, and pass validation policy.
- Modify `src/reporting.mjs`: display policy, provenance, timeout, truncation, and partial results.
- Modify `src/errors.mjs`: validation policy and timeout errors.
- Create/modify `test/process.test.mjs`, `test/validation.test.mjs`, `test/e2e.test.mjs`, and `test/importer.test.mjs`.

### Task 1: Define bounded process execution options

**Files:**
- Modify: `src/process.mjs`
- Modify: `src/errors.mjs`
- Create: `test/process.test.mjs`

**Interfaces:**
- Extend `runProcess(command, args, options)` with `envMode`, `timeoutMs`, `maxOutputBytes`, `killTree`, and `allowFailure`.
- Return `{ command, args, code, signal, stdout, stderr, stdoutTruncated, stderrTruncated, timedOut, killedTree, durationMs }`.

- [ ] **Step 1: Write failing timeout/output tests**

Add tests using `process.execPath`:

```js
test('runProcess kills a timed-out child and reports timeout', async () => {
  const result = await runProcess(process.execPath, ['-e', 'setTimeout(() => {}, 5000)'], {
    timeoutMs: 50, killTree: true, allowFailure: true
  });
  assert.equal(result.timedOut, true);
  assert.equal(result.killedTree, true);
});

test('runProcess caps stdout and reports truncation', async () => {
  const result = await runProcess(process.execPath, ['-e', 'console.log("x".repeat(1000))'], {
    maxOutputBytes: 32, allowFailure: true
  });
  assert.equal(result.stdoutTruncated, true);
  assert.ok(Buffer.byteLength(result.stdout) <= 32);
});
```

- [ ] **Step 2: Run focused tests and verify failure**

Run: `node --test test/process.test.mjs`

Expected: FAIL because the current process runner has no timeout, output cap, or tree-kill fields.

- [ ] **Step 3: Implement bounded capture**

Collect chunks only until `maxOutputBytes`, retain a truncation flag, and stop appending additional data. Start a timeout timer that calls the platform-specific tree killer and resolves after the child closes. Preserve `allowFailure` behavior for nonzero exits.

- [ ] **Step 4: Implement platform-specific tree termination**

On Windows, retain the spawned PID and invoke:

```text
taskkill.exe /PID <pid> /T /F
```

through a bounded internal process call with a recursion guard. On POSIX, spawn with `detached: true` and call `process.kill(-child.pid, 'SIGTERM')`, followed by `SIGKILL` if the group remains alive. Record the method and result in `killedTree`/`signal` fields.

- [ ] **Step 5: Run process tests on the current platform**

Run: `node --test test/process.test.mjs`

Expected: PASS, including Windows-specific assertions when `process.platform === 'win32'`.

- [ ] **Step 6: Commit bounded process execution**

```bash
git add src/process.mjs src/errors.mjs test/process.test.mjs
git commit -m "feat: bound validation child processes"
```
