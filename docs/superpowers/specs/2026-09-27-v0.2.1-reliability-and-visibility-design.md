# Agent Task Bridge v0.2.1 Reliability & Visibility Design

**Status:** Approved / Hardened Specification ready for implementation

**Date:** 2026-09-27

**Goal:** Resolve real-world task delegation friction by making worker reports durable and visible in local review workflows, diagnosing context coverage omissions and scope discrepancies at export time, and establishing a deterministic host-owned vs. worker-owned execution boundary in protocol capsules and review evidence.

**Approach:** Additive protocol and workflow hardening. Maintain `atb_protocol: "1.0"` and schema `1.1` compatibility while adding optional manifest metadata, git-aware context diagnostics, durable worker report storage, and a deterministic division of responsibility between external worker sandboxes and authoritative local host environments.

---

## 1. Context and Observed Evidence

Following the publication of Agent Task Bridge v0.2.0, the first real post-release cycle (delegating task F32 on `agenticwars-game-backup`) demonstrated that the v0.2 staging and safety mechanics worked properly (37 scoped file operations staged in an isolated worktree without active-tree pollution, clean drift checking, and immutable receipt generation). However, the cycle highlighted three significant operational gaps:

1. **Context-Coverage Blind Spot at Export:**
   The delegation request specified an `editable_scope` containing `docs/BACKLOG.md` and `project-progress/*`, but the explicit `files.editable` list omitted these files. The external worker correctly adhered to instructions not to fabricate files outside the embedded context snapshot, leaving the task partially blocked. The bridge gave no warning at export time that files matching the declared editable scope were omitted from the snapshot. Furthermore, if `files.editable` contains files *not* covered by `editable_scope`, the importer rejects them as `OUT_OF_SCOPE` on import, yet export provides no bidirectional validation.

2. **Incomplete Execution Boundaries:**
   The worker reported `partial_verification_blocked` because it lacked authoritative `pnpm` monorepo closure, full monorepo dependencies, and a live PostgreSQL instance (`DATABASE_URL`). These gates were outside the capsule's snapshot. Because the capsule did not explicitly partition worker-verifiable checks from host-owned gates, the worker felt compelled to mark the entire result blocked rather than completing the code deliverable and deferring host-level gates. Subsequently, host acceptance evidence marked the criteria as unverified failures, prompting inappropriate follow-up capsules.

3. **Invisible Worker Report (`REPORT.md`):**
   Although `inspectResultCapsule()` verified and extracted `REPORT.md` from the Result Capsule ZIP, `importResult()` never persisted the report or exposed its content in `review.json` or CLI output. The host agent and developer had to manually open and extract the ZIP archive to understand why the worker reported `partial` status and what assumptions it made.

## 2. Pillars of v0.2.1

### Pillar 1: Persisted Worker Report Visibility & Safety
- **Objective:** Ensure the external worker's findings, assumptions, validation claims, and unresolved items are durable, discoverable, and prominently rendered in review workflows.
- **Decompression Safety:** Impose a strict 512 KB uncompressed entry limit on `REPORT.md` during ZIP inspection to prevent memory exhaustion and zip bombs.
- **Durable Storage:** Persist `REPORT.md` to `.agent-task-bridge/tasks/<task-id>/imports/<import-id>/REPORT.md` during the persistence phase of `importResult()`. Preserve the report even if staging, drift check, or validation fails or is interrupted by signal.
- **Secret Scanning & Redaction:** Scan `REPORT.md` text with `scanSecretText()`. Do not block import; instead, redact high-confidence secrets in review structures (`review.workerReport`) and CLI output while preserving the raw report on disk within git-ignored bridge storage.
- **Review Model:** Extract structured sections (*Summary*, *Assumptions*, *Validation claims*, *Unresolved work*, *Findings*, *Recommendations*) and attach them alongside bounded raw markdown (capped at 64 KB) in `review.json` (`review.workerReport`).
- **Reporting:** Update `formatReviewReport()` and `formatImportReport()` to render the worker report directly in terminal and plugin views.

### Pillar 2: Bidirectional Context-Coverage & Scope Discrepancy Diagnostics
- **Objective:** Catch discrepancies between the declared `editable_scope` and the actual embedded `files.editable` payload before uploading to an external worker.
- **Git-Native File Discovery:** Use `git ls-files -z` (tracked files) and `git ls-files --others --exclude-standard -z` (untracked, non-ignored files) as the file candidate pool. This completely eliminates false-positive omission warnings on `.gitignore` files, build caches, and dependencies (`node_modules/`).
- **Binary File Screening:** Automatically screen out known binary extensions (`.png`, `.wasm`, `.jpg`, `.pdf`, `.zip`, etc.) so binary files in matching directories are not flagged as omitted context.
- **Negative Glob Support:** Support exclusion patterns prefixed with `!` (e.g. `!src/**/*.spec.ts`). A repository file is in scope if and only if it matches at least one positive pattern and no negative patterns. Negative patterns are never checked for file existence.
- **Bidirectional Diagnostics:**
  1. *Omission Check (`OMITTED_MATCHING_FILE`):* Tracked or untracked non-ignored text files matching `editable_scope` that are absent from `delegation.files` (capped at 50 findings with total count).
  2. *Inversion Check (`EDITABLE_OUTSIDE_SCOPE`):* Files declared in `delegation.files.editable` that do NOT match `editable_scope`. (Critical: these would otherwise be withheld as `OUT_OF_SCOPE` during import).
  3. *Literal Path Checks:* Distinguish between `INTENDED_NEW_OR_MISSING` (a literal path not currently on disk; noted as expected if intended for worker creation, or warned if a typo).
- **ReDoS Prevention & Performance:** Sanitize pattern wildcards (collapse consecutive `**`), pre-compile regular expressions once per pattern, cap file candidate scanning at 50,000 files, and ensure synchronous, sub-second execution.
- **Surfacing:** Emit non-blocking structured `warnings` in CLI export output, embed a prominent warning callout in the Task Capsule header, and add an alert item in the handoff checklist.

### Pillar 3: Execution Boundaries & Host-Owned Steps Protocol
- **Objective:** Clearly delineate what the external worker is expected to verify versus what is deferred to the authoritative local host environment.
- **Protocol & Manifest:** Add an optional `host_owned_steps: string[]` field to `delegation.json` and task capsule `manifest` (YAML frontmatter and `manifest.json`). For newly exported tasks in v0.2.1, default to:
  1. `"Authoritative monorepo/workspace test & build gates"`
  2. `"Live services, databases, and network credentials"`
  3. `"Git commit, branch creation, and repository push"`
- **Task Capsule Contract:** Add a dedicated `## Execution Boundaries & Responsibility Matrix` table in `TASK-CAPSULE-v1.md` and the rendered `.task.md`.
- **Worker Instructions:** Explicitly instruct the worker not to mark tasks failed or blocked purely because host-owned gates cannot run in the isolated sandbox. Return complete code deliverables and report deferred host gates in `REPORT.md`.
- **Deterministic Acceptance Evidence:** Update `buildAcceptanceEvidence()` in `src/evidence.mjs`:
  - Add `'deferred_to_host'` to `VALID_STATUSES`.
  - Deterministically match acceptance criteria against `host_owned_steps` using a 4-tier evaluation algorithm (explicit tagging, exact match, keyword category dictionaries, and worker claim cross-referencing).
  - Update `overallStatus` calculation: `blocked` > `unmet` > `unverified` > `deferred_to_host` > `verified_with_deferred` > `verified`.
- **Review Partial Classification:** In `src/review.mjs`, criteria with status `'deferred_to_host'` must NOT trigger `review.partial = true`. Set `review.hasDeferredSteps = true` and `review.deferredHostSteps = [...]` to prevent inappropriate `follow-up` loops with the external worker.

### Pillar 4: Coding Agent Skills & Plugin Tooling
- **Objective:** Ensure Claude Code and OpenAI Codex coding agents understand `host_owned_steps` and context coverage diagnostics during export and import workflows.
- **Skill Updates:** Update `export-chatgpt/SKILL.md` and `import-chatgpt/SKILL.md` across both plugin distributions.
- **Plugin Synchronization:** Maintain automated runtime bundling via `npm run bundle:plugins` and verify via `test/plugin-adapters.test.mjs`.

## 3. Detailed Architecture & Module Specifications

### 3.1 Glob Engine Hardening (`src/glob.mjs`)

#### Module Exports & Behavior
Update `src/glob.mjs` to export:
```javascript
export function compileGlob(pattern);
export function matchesGlob(repoPath, pattern);
export function matchesAnyScope(repoPath, patterns = []);
export function partitionScopePatterns(patterns = []);
```

#### Safe RegExp Compilation & ReDoS Defense
1. **Consecutive Wildcard Normalization:**
   - Collapse 3+ consecutive `*` to `**`.
   - Normalize repeated directory wildcards: replace `\*\*(\/\*\*)+` with `**`.
2. **Regex Translation Rules:**
   - `**` -> `(?:[^/]+/?)*` (or safely bounded non-backtracking equivalent)
   - `*` -> `[^/]*`
   - `?` -> `[^/]`
   - Escape regex metacharacters: `[\\^$+?.()|{}\[\]]`.
3. **Pattern Partitioning (`partitionScopePatterns`):**
   - Negative patterns: patterns starting with `!` (after trimming and normalization). Strip `!` and mark as `isNegative: true`.
   - Positive patterns: all patterns without `!`.
   - Returns `{ positive: CompiledPattern[], negative: CompiledPattern[] }`.
4. **Scope Matching Semantics (`matchesAnyScope`):**
   - Normalize candidate path using `normalizeRepoPath()`.
   - If positive patterns exist: candidate must match at least ONE positive pattern. (If no positive patterns are declared, matches nothing).
   - If candidate matches ANY negative pattern: match is REJECTED.
   - Pre-compile RegExp instances once when compiling the scope, avoiding per-file compilation in tight loops.

### 3.2 Context Coverage & Scope Diagnostics (`src/context.mjs`, `src/exporter.mjs`, `src/task-capsule.mjs`, `src/handoff.mjs`)

#### Known Binary Extensions Filter
In `src/context.mjs`, maintain `KNOWN_BINARY_EXTENSIONS`:
```javascript
const KNOWN_BINARY_EXTENSIONS = new Set([
  '.png', '.jpg', '.jpeg', '.gif', '.ico', '.webp', '.bmp', '.tiff',
  '.pdf', '.zip', '.tar', '.gz', '.tgz', '.7z', '.rar',
  '.woff', '.woff2', '.ttf', '.eot', '.otf',
  '.exe', '.dll', '.so', '.dylib', '.class', '.jar', '.bin', '.pyc', '.wasm',
  '.mp4', '.webm', '.mp3', '.wav', '.ogg', '.flac'
]);
```

#### File: `src/context.mjs`
`evaluateContextCoverage(repoRoot, delegation, selectedFiles, options = {})`:
1. **Inputs:**
   - `repoRoot`: absolute repository path.
   - `delegation`: validated delegation request object.
   - `selectedFiles`: array of files collected by `collectContext()` (or map of path -> role).
   - `options.maxRepoFiles`: maximum files to scan (default: 50,000).
   - `options.maxFindings`: maximum reported omissions (default: 50).
2. **Repository Candidate Discovery:**
   - Execute concurrently:
     - `git ls-files -z` (tracked files).
     - `git ls-files --others --exclude-standard -z` (untracked, non-gitignored files).
   - Combine into a deduplicated set of normalized POSIX paths.
   - Exclude `.git`, `.agent-task-bridge`, and paths matching `isBridgeMetadataPath()`.
   - If candidate count exceeds `options.maxRepoFiles`, truncate and set `candidateScanCapped: true`.
3. **Partition Scope Patterns:**
   - Partition `delegation.editable_scope` via `partitionScopePatterns()`.
   - Separate literal relative paths (containing no wildcard characters `*`, `?`, `[`, `]`) from glob patterns.
4. **Omission Evaluation (Scope -> Context):**
   - Map `selectedPaths = new Set(selectedFiles.map(f => f.path))`.
   - For each repository candidate:
     - Skip if file extension is in `KNOWN_BINARY_EXTENSIONS`.
     - Check if candidate matches `delegation.editable_scope`.
     - If matched AND NOT in `selectedPaths`:
       - Record as `{ path: candidate, reason: 'OMITTED_MATCHING_FILE' }`.
       - Increment `totalOmittedCount`.
       - Keep first `maxFindings` items in `omittedFiles`.
5. **Inversion Evaluation (Context -> Scope):**
   - For each path in `delegation.files.editable ?? []`:
     - If `!matchesAnyScope(path, delegation.editable_scope)`:
       - Record in `scopeViolations: [{ path, reason: 'EDITABLE_OUTSIDE_SCOPE', message: 'File is in files.editable but not covered by editable_scope; will be withheld as OUT_OF_SCOPE on import' }]`.
6. **Literal Path Evaluation:**
   - For each positive literal path in `delegation.editable_scope`:
     - If file does not exist on disk in `repoRoot`:
       - Check if mentioned in `deliverables` or `objective`.
       - If planned for creation, classify as `{ path, reason: 'INTENDED_NEW_FILE' }`.
       - Otherwise, classify as `{ path, reason: 'NOT_FOUND_IN_REPO', message: 'Literal scope path not found in repository' }`.
7. **Diagnostic Summary Output:**
   ```typescript
   interface ContextCoverageReport {
     hasGaps: boolean;
     totalOmittedCount: number;
     omittedFiles: Array<{ path: string; pattern?: string; reason: string }>;
     scopeViolations: Array<{ path: string; reason: string; message: string }>;
     missingRepoPaths: Array<{ path: string; reason: string; message?: string }>;
     candidateScanCapped: boolean;
   }
   ```
   `hasGaps` is `true` if `totalOmittedCount > 0` or `scopeViolations.length > 0` or `missingRepoPaths.length > 0`.

#### File: `src/exporter.mjs`
- Invoke `evaluateContextCoverage(root, delegation, context.files)` during `exportTask()`.
- If `coverage.hasGaps` is true:
  - Add structured entry to `warnings` array:
    ```javascript
    warnings.push({
      code: 'CONTEXT_COVERAGE_GAP',
      message: `Detected ${coverage.totalOmittedCount} omitted scope file(s) and ${coverage.scopeViolations.length} scope violation(s)`,
      details: coverage,
    });
    ```
  - Pass `coverage` into `renderTaskCapsule()` and `createHandoffBundle()`.
  - Include `coverage` in return payload of `exportTask()`.

#### File: `src/task-capsule.mjs`
- In `renderTaskCapsule()`:
  If `coverage?.hasGaps` is true, render a prominent warning block directly under `# Agent Task Bridge — Task Capsule`:
  ```markdown
  > [!WARNING]
  > **Context Coverage Notice:**
  > - Omitted matching files (${coverage.totalOmittedCount}):
  >   - `docs/BACKLOG.md`
  >   - `project-progress/Tasks.md`
  >   ...
  > External worker: work strictly within the provided embedded files. Do not fabricate or assume missing files. Document any omissions preventing full completion in `REPORT.md`.
  ```
  If `coverage?.scopeViolations?.length > 0`:
  ```markdown
  > [!CAUTION]
  > **Scope Configuration Notice:** The following files are in `files.editable` but not covered by `editable_scope`:
  > - `src/utils/math.ts`
  > Note: Changes to these files will be withheld by the bridge on import unless `editable_scope` is updated.
  ```

#### File: `src/handoff.mjs`
- In `createHandoffBundle()`:
  Add an item in `checklist.md`:
  `- [ ] Note: Context coverage gap detected: ${coverage.totalOmittedCount} matching files omitted; ${coverage.scopeViolations.length} scope violations.`

### 3.3 Worker Report Storage, Safety & Review (`src/result-capsule.mjs`, `src/importer.mjs`, `src/review.mjs`, `src/reporting.mjs`)

#### File: `src/result-capsule.mjs`
1. **Entry Size Bound on `REPORT.md`:**
   - Define `MAX_REPORT_UNCOMPRESSED_BYTES = 512 * 1024` (512 KB).
   - During `inspectResultCapsule()`:
     If archive contains `REPORT.md`:
     - Inspect raw uncompressed length from entry: if `entry.data.length > MAX_REPORT_UNCOMPRESSED_BYTES`, throw:
       `new AtbError('REPORT_TOO_LARGE', 'REPORT.md exceeds maximum allowed size of 512 KB')`.
     - Decode using `decodeText(entry.data, 'REPORT.md')`.
2. **Secret Screening:**
   - Run `scanSecretText(reportText)`.
   - Do NOT throw an error or reject the archive.
   - Return `{ manifest, report, reportFindings, files, entryNames, archive_sha256 }`.

#### Worker Report Parsing: `src/reporting.mjs`
Introduce `parseWorkerReport(rawText, options = {})`:
1. **Section Heading Matchers:**
   Case-insensitive regular expressions matching Markdown headers `#`, `##`, `###`, or bold prefixes:
   - Summary: `/^(?:#{1,3}\s*|\*\*)\s*(?:summary|overview)\b/im`
   - Assumptions: `/^(?:#{1,3}\s*|\*\*)\s*(?:assumptions?)\b/im`
   - Validation Claims: `/^(?:#{1,3}\s*|\*\*)\s*(?:validation\s*claims?|tested|testing\s*claims?)\b/im`
   - Unresolved Work: `/^(?:#{1,3}\s*|\*\*)\s*(?:unresolved(?:\s*work)?|follow-?up|open\s*issues?|deferred)\b/im`
   - Findings: `/^(?:#{1,3}\s*|\*\*)\s*(?:findings?|analysis)\b/im`
   - Recommendations: `/^(?:#{1,3}\s*|\*\*)\s*(?:recommendations?|next\s*steps?)\b/im`
2. **Secret Redaction:**
   - If `options.findings` contains high-confidence secret findings:
     Redact matching patterns in parsed text sections: replace with `[REDACTED_SECRET:<category>]`.
3. **Structured Model:**
   ```typescript
   interface WorkerReportData {
     present: boolean;
     path: string | null;
     summary: string;
     assumptions: string[];
     validationClaims: string[];
     unresolved: string[];
     findings: string[];
     recommendations: string[];
     privacyFindings: Array<{ category: string; detail: string }>;
     rawText: string; // capped at 64 KB
     truncated: boolean;
   }
   ```
4. **Fallback:**
   If no standard headings are found, extract the first non-empty paragraph as `summary` and preserve raw text up to 64 KB.

#### File: `src/importer.mjs`
1. **Persistence Phase & Lifecycle Resilience:**
   - In `importResult()`:
     When `taskId` and `importId` are determined, define `workerReportPath = path.join(atbRoot(root), 'tasks', taskId, 'imports', importId, 'REPORT.md')`.
   - In the `finally` block of `importResult()`:
     - If `result?.report` is non-null:
       - Ensure import directory exists: `await mkdir(path.dirname(workerReportPath), { recursive: true })`.
       - Write raw unredacted `result.report` to disk at `workerReportPath`.
       - Record `report.workerReportPath = workerReportPath`.
       - Call `parseWorkerReport(result.report, { findings: result.reportFindings })`.
       - Pass `workerReport` to `buildReviewData()`.
     - Crucial: `REPORT.md` is preserved even when lifecycle state is `failed`, `rejected`, or `interrupted`. It is NEVER cleaned up by `cleanupIsolatedStaging` (which only touches the temporary external worktree).
2. **Review Data Integration:**
   - Pass `workerReport` to `buildReviewData({ repoRoot, importReport, lifecycle, receipt, workerReport })`.

#### File: `src/review.mjs`
`buildReviewData({ repoRoot, importReport, lifecycle, receipt, workerReport })`:
- Attach `workerReport` to the returned review JSON object.
- **Review Partial Evaluation Rule:**
  ```javascript
  const hasUnresolvedWorkerCriteria = (importReport?.acceptance?.criteria ?? []).some(
    (criterion) => criterion.status === 'unverified' || criterion.status === 'unmet' || criterion.status === 'blocked'
  );
  const hasDeferredHostCriteria = (importReport?.acceptance?.criteria ?? []).some(
    (criterion) => criterion.status === 'deferred_to_host'
  );
  const partial = Boolean(
    importReport?.resultStatus === 'partial' || importReport?.resultStatus === 'blocked' || importReport?.resultStatus === 'research-only'
    || withheldFiles.length > 0 || validation?.blocked || validation?.skipped
    || hasUnresolvedWorkerCriteria
  );
  ```
- Set `deferredToHost: hasDeferredHostCriteria`.
- Set `deferredHostSteps: (importReport?.acceptance?.criteria ?? []).filter(c => c.status === 'deferred_to_host').map(c => c.text)`.

#### File: `src/reporting.mjs`
- `formatImportReport(report)`:
  Display `Worker Report: present (.agent-task-bridge/tasks/.../REPORT.md)` (and privacy warnings if any secrets were redacted).
- `formatReviewReport(review)`:
  If `review.workerReport?.present`:
  Render a dedicated `# Worker Report (REPORT.md)` section:
  - **Summary:** `review.workerReport.summary`
  - **Assumptions:** bulleted list (or `_None reported_`)
  - **Validation Claims:** bulleted list
  - **Unresolved / Follow-up:** bulleted list
  If `review.deferredToHost`:
  Render a dedicated `# Deferred Host Steps` section:
  - List of steps requiring local host verification, reminding the user that these are host-owned gates, not worker defects.

2. **Capsule Markdown Section:**

   ```markdown
   ## Execution Boundaries & Responsibility Matrix

   | Domain | External Worker (ChatGPT) | Host Agent (Local Bridge) |
   |---|---|---|
   | **Code Changes** | Implement complete files strictly within embedded `files.editable`. | Inspects staged diff and applies changes via `integrate --confirm`. |
   | **Verification** | Execute self-contained syntax and unit tests possible within capsule. | Runs authoritative local validation scripts in isolated staging. |
   | **Infrastructure** | Do NOT attempt to run live databases or external network services. | Manages local environment, live services, and toolchains. |
   | **Version Control** | Do NOT generate git commits, patches, or branches. | Owns git commit, branch merge, and remote push. |

   - Authoritative monorepo format/lint/check/test/build
   - Live database migrations and connection gates
   - Git branch integration, commit, and remote push

   *Worker Instruction:* Do not mark a task failed or hallucinate results solely because host-owned steps cannot run in your sandbox. Return the code changes, set status `complete` (or `partial` if code is unfinished), and list deferred host steps in `REPORT.md`.
   ```

#### Acceptance Evidence: `src/evidence.mjs`
1. **Valid Statuses:**
   Update `VALID_STATUSES`:
   ```javascript
   const VALID_STATUSES = new Set(['verified', 'unverified', 'unmet', 'blocked', 'deferred_to_host']);
   ```
2. **Deterministic Host-Step Matching Algorithm:**
   Introduce `isHostOwnedCriterion(criterionText, hostOwnedSteps = [], workerClaim = null)`:
   - **Tier 1 (Explicit Prefix / Exact Match):**
     - Case-insensitive check if `criterionText` starts with `[host]`, `[host-owned]`, `(host)`, or `host-owned:`.
     - Exact or case-insensitive match against any entry in `hostOwnedSteps`.
   - **Tier 2 (Keyword Category Dictionaries):**
     Category dictionaries matched only when corresponding category exists in `hostOwnedSteps`:
     - *Database / Service Gates:*
       If `hostOwnedSteps` contains terms like `database`, `service`, `migration`, `live`:
       Criterion matches if it contains any of `/\b(?:database|postgres(?:ql)?|mysql|redis|mongodb|docker|service|migration)\b/i`.
     - *Monorepo / Workspace Gates:*
       If `hostOwnedSteps` contains terms like `monorepo`, `workspace`, `authoritative`, `build`:
       Criterion matches if it contains any of `/\b(?:monorepo|workspace|pnpm|turbo|full\s+(?:build|test)|authoritative)\b/i`.
     - *VCS / CI / Push Gates:*
       If `hostOwnedSteps` contains terms like `git`, `branch`, `commit`, `push`:
       Criterion matches if it contains any of `/\b(?:git\s+push|git\s+commit|merge|remote\s+branch|ci\/cd|pipeline)\b/i`.
   - **Tier 3 (Worker Claim Cross-Reference):**
     - If the worker claim explicitly notes `deferred_to_host` or states the step is host-owned, and the criterion matches a Tier 2 dictionary, classify as `deferred_to_host`.
3. **Evidence Derivation:**
   In `criterionEvidence(text, result, localState, hostOwnedSteps)`:
   - Check `isHostOwnedCriterion(text, hostOwnedSteps, claim)`:
     If true:
     `evidence.push('Step is declared as host-owned and will be verified locally by host agent.');`
     `return { status: 'deferred_to_host', evidence };`
4. **Overall Status Calculation:**
   ```javascript
   const hasBlocked = normalized.some((c) => c.status === 'blocked');
   const hasUnmet = normalized.some((c) => c.status === 'unmet');
   const hasUnverified = normalized.some((c) => c.status === 'unverified');
   const hasDeferred = normalized.some((c) => c.status === 'deferred_to_host');
   const allDeferred = normalized.length > 0 && normalized.every((c) => c.status === 'deferred_to_host');

   const overallStatus = hasBlocked
     ? 'blocked'
     : hasUnmet
       ? 'unmet'
       : hasUnverified
         ? 'unverified'
         : allDeferred
           ? 'deferred_to_host'
           : hasDeferred
             ? 'verified_with_deferred'
             : 'verified';
   ```
5. **Backwards Compatibility:**
   - If `task.manifest.host_owned_steps` is not present (v0.1 or v0.2.0 capsules):
     Pass `hostOwnedSteps = []`. No criteria are automatically reclassified as `deferred_to_host` unless explicitly tagged in the criterion text. All existing v0.2.0 test suites and capsules produce identical results.

## 4. Error Handling, Edge Cases & Safety Invariants

1. **Active Worktree Preservation:**
   All context coverage checks use read-only Git plumbing (`git ls-files -z`, `git ls-files --others --exclude-standard -z`). The working tree and index remain completely untouched.
2. **Untrusted Worker Report Handling:**
   `REPORT.md` is strictly untrusted worker text. It is size-bounded to 512 KB to avoid decompression DoS, scanned for secrets, bounded to 64 KB in `review.json`, and its assertions are never treated as authoritative local evidence.
3. **Secret Redaction Without Workflow Breakage:**
   Detected secrets in `REPORT.md` are masked in review structures (`[REDACTED_SECRET:<category>]`) and terminal output to prevent accidental leakages, while preserving the raw report on disk within git-ignored `.agent-task-bridge/` storage for local developer review.
4. **Non-blocking Diagnostics:**
   Context coverage warnings never abort the export command, allowing developers to export deliberately slice-bounded context when desired.
5. **No Infinite Follow-Up Loops:**
   Because `deferred_to_host` criteria do NOT set `review.partial = true`, coding agents will not erroneously trigger recursive `follow-up` capsules to external workers for host-owned gates.
6. **Graceful Backward Compatibility:**
   Capsules lacking `host_owned_steps` default to empty lists on import. Result Capsules without `REPORT.md` handle gracefully (`present: false`). Existing tests continue to pass without regression.
