# Gemini Support and Task Planning Skill Design

**Status:** Draft for approval  
**Date:** 2026-11-23  
**Goal:** Add first-class Gemini host-agent support (Gemini CLI and Antigravity CLI/IDE) to Agent Task Bridge (`relay`), and add a structured task-breakdown and planning skill (`plan-chatgpt`) across all host providers (Gemini, Claude Code, and Codex) so the coding agent can analyze, decompose, create seams, export tasks to ChatGPT, and import/integrate results.

---

## 1. Intent and Why

Developers using Gemini as their coding agent (via Gemini CLI or Antigravity CLI/IDE) want the same local-first task delegation workflow available in Claude Code and Codex:
1. Analyze a feature or request, break it down along clean module/interface seams into local host-owned wiring vs. bounded exportable units, and prepare the seam first.
2. Export each bounded unit to a Task Capsule (`--source-agent gemini`) for execution in ChatGPT.
3. Import, validate, review, and integrate the returned Result Capsule (`.zip` or `reply.md`) without risking unreviewed modifications to the active working tree.

Previously, step 1 ("Plan locally and split along the seams") was only described as prose in `README.md` rather than packaged as an invocable agent skill, and only `claude-code` and `codex` had plugin bundles under `plugins/`.

---

## 2. Goals, Non-Goals, and Anti-Goals

### Goals
- **Self-contained `plugins/gemini/` bundle:** Mirror `plugins/claude-code` and `plugins/codex` with a generated `runtime/` copy via `scripts/bundle-plugins.mjs`, provider manifests (`.gemini-plugin/plugin.json` and `gemini-extension.json`), skills (`plan-chatgpt`, `export-chatgpt`, `import-chatgpt`), and `plugins/gemini/README.md`.
- **Dual Gemini surface compatibility with strict validation:**
  - **Antigravity CLI/IDE:** `agy plugin validate --strict plugins/gemini` passes with 0 errors and 0 warnings (`.gemini-plugin/plugin.json` and `skills/`, without placing `commands/` inside `plugins/gemini/` because Antigravity native plugins warn on `commands/`). Workspace discovery via `.agents/plugins.json` uses `"include_only": ["gemini"]` so `plugins/claude-code` and `plugins/codex` are not scanned.
  - **Gemini CLI:** `gemini extensions validate .` and `gemini extensions validate plugins/gemini` both pass with 0 errors. Because `gemini extensions install <repo-url>` clones the repository root and Gemini CLI loads `<extensionDir>/skills/*/SKILL.md` and `<extensionDir>/commands/*.toml` directly relative to `gemini-extension.json`, `scripts/bundle-plugins.mjs` also synchronizes `plugins/gemini/skills/` into root `skills/` and maintains root `commands/*.toml` alongside root `gemini-extension.json`.
- **Top-level and subdirectory installation:** Support installing directly from `plugins/gemini` (`agy plugin install ./plugins/gemini`, `agy plugin install https://github.com/AndriiLavrekha/relay/tree/main/plugins/gemini`, or `gemini extensions link ./plugins/gemini`) as well as root-level installs (`gemini extensions install https://github.com/AndriiLavrekha/relay` or `gemini extensions link .`) and workspace discovery (`.agents/plugins.json`).
- **New `plan-chatgpt` skill across providers (`gemini`, `claude-code`, `codex`):** Give all three host agents a dedicated skill to analyze a feature or backlog item, decompose it into bounded exportable units vs. host-owned integration seams, create/commit the interface seam first, and draft delegation JSON specs ready for `export-chatgpt`.
- **Automated test and smoke coverage:** Extend `test/plugin-adapters.test.mjs` and `scripts/smoke-test.mjs` to verify `plugins/gemini` runtime parity, root `skills/` parity, manifest fields, skills (`plan-chatgpt`, `export-chatgpt`, `import-chatgpt`), Gemini CLI command TOML definitions, and cross-provider round-trip execution with `--source-agent gemini`.

### Non-Goals
- No changes to the Task Capsule v1 or Result Capsule v1 protocol (`atb_protocol: "1.0"`, `schema_version: "1.1"`).
- No automated Gemini API or ChatGPT API transport.
- No changes to deterministic archive inspection, privacy scanning, drift rules, or isolated worktree staging.

### Anti-Goals
- Diverging core runtime logic between Gemini, Claude Code, and Codex. All three must run identical copies of `src/` and `bin/` generated by `npm run bundle:plugins`.
- Having `plan-chatgpt` automatically export capsules or mutate production logic before the developer confirms the unit breakdown and interface seam.

---

## 3. Constraints

- Zero third-party runtime npm dependencies; Node.js >= 22 native ESM.
- `npm run bundle:plugins` must remain idempotent: it populates `plugins/<provider>/runtime/` for `claude-code`, `codex`, and `gemini`, and syncs `plugins/gemini/skills/` to root `skills/` so top-level Gemini CLI extension installs load the exact same skills.
- `agy plugin validate --strict plugins/gemini`, `gemini extensions validate plugins/gemini`, and `gemini extensions validate .` must all pass with 0 errors and 0 warnings.
- Existing Claude Code (`.claude-plugin/marketplace.json`) and Codex (`.agents/plugins/marketplace.json`) marketplaces must continue to validate and work unchanged.

---

## 4. Approaches Considered

1. **Approach A — Dedicated `plugins/gemini/` bundle + root Gemini CLI extension layout (`gemini-extension.json`, `commands/`, synced `skills/`) + scoped `.agents/plugins.json` + cross-provider `plan-chatgpt` skill (Selected)**
   - Adds `plugins/gemini/` to `scripts/bundle-plugins.mjs` alongside `claude-code` and `codex`.
   - Places `.gemini-plugin/plugin.json`, `gemini-extension.json`, `README.md`, and `skills/` inside `plugins/gemini/` (keeping `commands/` out of `plugins/gemini/` so `agy plugin validate --strict plugins/gemini` passes with zero warnings).
   - Places `gemini-extension.json`, `commands/*.toml`, and bundle-synced `skills/` at the repository root so `gemini extensions install <repo-url>` and `gemini extensions link .` load both slash commands and agent skills in Gemini CLI.
   - Configures `.agents/plugins.json` with `{ "entries": [{ "path": "plugins", "include_only": ["gemini"] }] }` so Antigravity discovers only `plugins/gemini` without colliding with `plugins/claude-code` or `plugins/codex`.
   - Adds `skills/plan-chatgpt/SKILL.md` to `plugins/gemini/`, `plugins/claude-code/`, and `plugins/codex/`.
   - *Trade-off:* Root `skills/` is synced from `plugins/gemini/skills/` by `npm run bundle:plugins` and verified for byte-identical parity in `test/plugin-adapters.test.mjs`.

2. **Approach B — `plugins/gemini/` subdirectory only (no root `gemini-extension.json`, `commands/`, or `skills/`)**
   - Omits root-level Gemini CLI extension files.
   - *Trade-off:* `gemini extensions install https://github.com/AndriiLavrekha/relay` fails because Gemini CLI clones the repository root and requires `gemini-extension.json`, `skills/`, and `commands/` at the root of the cloned repo.

3. **Approach C — Root-level Gemini files only (no `plugins/gemini/`)**
   - *Trade-off:* Breaks the uniform `plugins/<provider>/` architecture, prevents self-contained subdirectory installs (`agy plugin install ./plugins/gemini`), and causes `agy plugin validate --strict` to warn on root `commands/`.

---

## 5. Detailed Design

### 5.1 `plugins/gemini/` and Root Layout

```text
plugins/gemini/
├── .gemini-plugin/
│   └── plugin.json
├── gemini-extension.json
├── README.md
├── skills/
│   ├── plan-chatgpt/
│   │   └── SKILL.md
│   ├── export-chatgpt/
│   │   └── SKILL.md
│   └── import-chatgpt/
│       └── SKILL.md
└── runtime/                  # generated by npm run bundle:plugins
    ├── package.json
    ├── bin/
    │   └── agent-task-bridge.mjs
    └── src/
        └── *.mjs

<repo-root>/
├── gemini-extension.json     # top-level Gemini CLI extension manifest
├── commands/                 # top-level Gemini CLI slash commands (/plan-chatgpt, /export-chatgpt, /import-chatgpt)
│   ├── plan-chatgpt.toml
│   ├── export-chatgpt.toml
│   └── import-chatgpt.toml
├── skills/                   # generated/synced from plugins/gemini/skills/ by npm run bundle:plugins
│   ├── plan-chatgpt/
│   │   └── SKILL.md
│   ├── export-chatgpt/
│   │   └── SKILL.md
│   └── import-chatgpt/
│       └── SKILL.md
└── .agents/
    ├── plugins.json          # Antigravity workspace discovery scoped via include_only: ["gemini"]
    └── plugins/
        └── marketplace.json  # existing Codex local marketplace (unchanged)
```

- **`plugins/gemini/.gemini-plugin/plugin.json`**:
  ```json
  {
    "name": "task-bridge",
    "displayName": "Agent Task Bridge",
    "version": "0.3.3",
    "description": "Plan, export, and safely import bounded repository work delegated to ChatGPT.",
    "author": {
      "name": "Agent Task Bridge contributors"
    },
    "repository": "https://github.com/AndriiLavrekha/relay",
    "homepage": "https://github.com/AndriiLavrekha/relay",
    "license": "MIT",
    "category": "Developer Tools",
    "keywords": ["chatgpt", "delegation", "handoff", "gemini", "antigravity", "developer-tools"]
  }
  ```
- **`gemini-extension.json`** (in `plugins/gemini/gemini-extension.json` and at repo root `gemini-extension.json`):
  ```json
  {
    "name": "task-bridge",
    "version": "0.3.3",
    "description": "Plan, export, and safely import bounded repository work delegated to ChatGPT."
  }
  ```
- **`.agents/plugins.json`** (scoped workspace discovery for Antigravity):
  ```json
  {
    "entries": [
      {
        "path": "plugins",
        "include_only": ["gemini"]
      }
    ]
  }
  ```
  *Why `include_only: ["gemini"]` is required:* Antigravity scans each `entries[].path` directory one level deep. Because `plugins/` also contains `claude-code` and `codex`, omitting `include_only` would cause Antigravity to ingest `plugins/claude-code` and `plugins/codex` and collide on duplicate skill names.
- **Why `commands/` lives at the repo root and not inside `plugins/gemini/`**:
  - Antigravity's native plugin validator (`agy plugin validate --strict plugins/gemini`) treats any directory with `.gemini-plugin/plugin.json` as a native plugin and emits a warning (`⚠ commands: never loaded: plugins have no commands`) if `commands/` is present inside `plugins/gemini/`.
  - Keeping `commands/*.toml` at the repository root satisfies `gemini extensions install https://github.com/AndriiLavrekha/relay` and `gemini extensions link .` while keeping `plugins/gemini/` warning-free under `agy plugin validate --strict`.

### 5.2 Skills (`plan-chatgpt`, `export-chatgpt`, `import-chatgpt`)

1. **`plan-chatgpt` (`skills/plan-chatgpt/SKILL.md` in `gemini`, `claude-code`, and `codex`)**:
   - **Frontmatter:**
     - `name: plan-chatgpt`
     - `description: Plan and decompose a feature or multi-part task along clean module seams into local host-owned work and bounded units ready to export to ChatGPT.`
     - (`plugins/claude-code/skills/plan-chatgpt/SKILL.md` also includes `argument-hint: "[feature or task to plan and split]"` to match existing Claude Code skill conventions.)
   - **Runtime path reference:** Each provider's `plan-chatgpt/SKILL.md` references the provider's CLI path convention (`${CLAUDE_PLUGIN_ROOT}/runtime/bin/agent-task-bridge.mjs` in Claude Code; `<plugin root>/runtime/bin/agent-task-bridge.mjs` in Codex and Gemini, with `<plugin root>/bin/agent-task-bridge.mjs` fallback for root Gemini CLI installs) so the agent knows how `export-chatgpt` will invoke the bridge once the user approves the plan.
   - **Workflow:**
     1. Inspect the user's goal, relevant modules, types/contracts, existing tests, and Git status. Do not export anything during planning.
     2. Split the work along clean seams into a structured breakdown:
        - **Delegate to ChatGPT:** self-contained modules behind an interface, parsers/algorithms, isolated test suites, or isolated file migrations.
        - **Keep local (Host-owned):** cross-cutting registration, dependency injection, routing, config, live services, and edits spread across many files.
     3. For each exportable unit, draft the exact delegation contract fields:
        - `title`, `objective`, `work_unit`, `work_type`, `current_work_state`, `deliverables`, `non_goals`, and `architecture_context`
        - `editable_scope` globs
        - `files.editable`, `files.contract`, `files.reference` (1 neighboring source file + 1 existing test), `files.validation`, `files.configuration`
        - observable `acceptance_criteria` and `host_owned_steps`
        - dependency ordering (which units can be exported in parallel vs. sequentially).
     4. Propose the **seam commit** first (adding or updating interfaces, types, and minimal stubs locally so ChatGPT implements against a real contract in `HEAD`).
     5. Stop and get explicit developer confirmation on the unit breakdown (and whether to create/commit the seam first) before invoking `export-chatgpt` for any unit.

2. **`export-chatgpt` (`plugins/gemini/skills/export-chatgpt/SKILL.md`, synced to `skills/export-chatgpt/SKILL.md`)**:
   - Mirrors the Codex/Claude Code export skill.
   - **Deterministic CLI path resolution:** The skill lives at `<root>/skills/export-chatgpt/SKILL.md`, so `<root>` is two directories above `SKILL.md` (`path.resolve(skillDir, '../..')`, which is also the directory containing `.gemini-plugin/plugin.json` or `gemini-extension.json`). Resolve the CLI entrypoint in order:
     1. `<root>/runtime/bin/agent-task-bridge.mjs` (when loaded from `plugins/gemini`, `agy plugin install`, or `.agents/plugins.json`)
     2. `<root>/bin/agent-task-bridge.mjs` (when installed or linked from the repository root via `gemini extensions install` / `gemini extensions link .`).
   - Always invoke using the resolved absolute path from the target repository root (`--repo .`); never assume `<root>` is the current working directory.
   - Runs `node "<resolved-cli-path>" export --delegation "<temp-json>" --repo . --source-agent gemini [--max-tokens <budget>]`.
   - Reports `task.md`, `kickoff.md`, scope, file count, token estimate, and any `CONTEXT_COVERAGE_GAP` / `EDITABLE_OUTSIDE_SCOPE` warnings.

3. **`import-chatgpt` (`plugins/gemini/skills/import-chatgpt/SKILL.md`, synced to `skills/import-chatgpt/SKILL.md`)**:
   - Mirrors the Codex/Claude Code import skill and uses the same two-step `<root>/runtime/bin/agent-task-bridge.mjs` -> `<root>/bin/agent-task-bridge.mjs` CLI resolution from `<root>` (two directories above `SKILL.md`).
   - Runs `node "<resolved-cli-path>" import "<result.zip or reply.md>" --repo . --brief`.
   - Guides the Gemini agent through inspecting drift statuses (`CLEAN_UNCHANGED`, `NEW_EXPECTED`, `MERGED_CLEAN`, `SUSPECT_ELISION`, `LOCAL_CHANGED`), validation evidence, persisted `review.workerReport` (`REPORT.md`), `deferred_to_host` criteria, `follow-up <import-id>`, and confirmation-gated `integrate <import-id> --mode branch --branch <name> --confirm`.

### 5.3 Gemini CLI Slash Commands (`commands/*.toml`)

Gemini CLI turns `<extensionDir>/commands/<name>.toml` into `/plan-chatgpt`, `/export-chatgpt`, and `/import-chatgpt` slash commands when installed from the repository root:
- `commands/plan-chatgpt.toml`: sets `description` and `prompt` instructing the agent to use the `plan-chatgpt` skill for `{{args}}` (and stop for confirmation before exporting).
- `commands/export-chatgpt.toml`: sets `description` and `prompt` instructing the agent to use the `export-chatgpt` skill with `--source-agent gemini` for `{{args}}`.
- `commands/import-chatgpt.toml`: sets `description` and `prompt` instructing the agent to use the `import-chatgpt` skill to safely stage, validate, and review `{{args}}` without modifying the active working tree.

### 5.4 Build, Packaging, Smoke Test, and Documentation Updates

- **`scripts/bundle-plugins.mjs`**:
  - Loop over `['claude-code', 'codex', 'gemini']` to bundle `src/`, `bin/`, and `package.json` into `plugins/<provider>/runtime/`.
  - Sync `plugins/gemini/skills/` into root `skills/` (`rm` + `cp({ recursive: true })`) so root Gemini CLI extension installs always match `plugins/gemini/skills/`.
- **`package.json`**:
  - Include `"gemini-extension.json"`, `"commands"`, `"skills"`, and `"docs/superpowers/specs/2026-11-23-gemini-support-design.md"` in `files` (alongside existing `"plugins"` and `".agents"`).
- **`scripts/smoke-test.mjs`**:
  - Include `'gemini'` in the provider runtime version check and `providerRuntimes` output array.
  - Add a cross-provider smoke flow exercising `gemini` (e.g., `gemini -> ChatGPT -> claude-code` or `codex -> ChatGPT -> gemini`) to verify end-to-end export/import with `--source-agent gemini`.
- **`README.md` & `docs/architecture.md`**:
  - Add Gemini (Gemini CLI & Antigravity) to badges, Quick Start, Install, Upgrade, and Architecture diagrams.
  - Document the new `plan-chatgpt` skill in the *"Delegating a feature"* section across Claude Code, Codex, and Gemini.
- **`test/plugin-adapters.test.mjs`**:
  - Expand the runtime parity loop to `['claude-code', 'codex', 'gemini']`.
  - Verify that root `skills/<name>/SKILL.md` is byte-identical to `plugins/gemini/skills/<name>/SKILL.md` for `plan-chatgpt`, `export-chatgpt`, and `import-chatgpt`.
  - Verify `plugins/gemini/.gemini-plugin/plugin.json`, `plugins/gemini/gemini-extension.json`, root `gemini-extension.json`, `.agents/plugins.json` (`include_only: ["gemini"]`), root `commands/*.toml`, `plugins/gemini/README.md`, and the `plan-chatgpt`, `export-chatgpt`, and `import-chatgpt` skills across all three providers.
